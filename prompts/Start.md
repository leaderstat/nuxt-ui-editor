### 7. Цветовая схема и подсветка

Основной фон редактора — чёрный или угольно-серый.

Рекомендуемые цвета:

- Background: `#151719`
- Editor background: `#1C1F22`
- Text: `#E5E7EB`
- Green: `#22C55E`
- Yellow: `#EAB308`
- Red: `#EF4444`

Реализовать подсветку **в Панели 2** на основании результатов сравнения с Панелью 1.

**ЗЕЛЁНЫЙ — полное совпадение**

Строка полностью совпадает с одной из строк исходного документа.

Условие:

`HASH(reviewLine) == HASH(sourceLine)`

При совпадении контрольной суммы обязательно выполнить проверку полного текста, чтобы исключить коллизии.

Зелёная подсветка применяется ко всей строке.

**ЖЁЛТЫЙ — частичное совпадение**

Совпадает HASH-HALF, но полного совпадения нет.

Условие:

`HASH_HALF(reviewLine) == HASH_HALF(sourceLine)`

При этом полный HASH не подтверждает совпадение.

Жёлтая подсветка означает, что начало строки совпадает с началом строки исходного документа.

Проверять фактическое содержимое сравниваемых префиксов для исключения коллизий.

**КРАСНЫЙ — совпадений нет**

Ни полный HASH, ни HASH-HALF не дали подтверждённого совпадения.

Такая строка считается уникальной относительно исходного документа.

Подсветку делать реактивной.

После изменения текста необходимо обновлять статус соответствующих строк.

Приоритет классификации:

1. Полное совпадение — GREEN.
2. Частичное совпадение — YELLOW.
3. Отсутствие совпадений — RED.

### 8. Алгоритм HASH и HASH-HALF

Реализовать два механизма сравнения строк.

**HASH**

В соответствии с заданной спецификацией:

HASH строки — сумма числовых значений всех байтов UTF-8.

Алгоритм:

1. Получить строку.
2. Закодировать её в UTF-8.
3. Получить массив байтов.
4. Просуммировать числовые значения байтов.
5. Сохранить результат в SQLite.

Пример TypeScript:

```ts
function calculateHash(text: string): number {
  const bytes = new TextEncoder().encode(text)

  return bytes.reduce(
    (sum, byte) => sum + byte,
    0
  )
}
```

**Важно:** это простая аддитивная контрольная сумма, а не криптографический HASH. Разные строки могут иметь одинаковую сумму.

Для надёжности сохранять дополнительный криптографический digest (например, SHA-256) или выполнять точное сравнение строк после нахождения кандидатов.

Не заменять заданный аддитивный алгоритм без согласования.

**HASH-HALF**

Вычисляется строго от начала строки до её середины.

Алгоритм:

1. Получить UTF-8 представление строки.
2. Определить середину строки.
3. Взять первую половину.
4. Вычислить сумму байтов UTF-8 первой половины.
5. Сохранить HASH-HALF в SQLite.

Для корректной работы с Unicode определять половину по Unicode code points, не разрывая многобайтовые символы и суррогатные пары.

Пример:

```ts
function calculateHashHalf(text: string): number {
  const characters = Array.from(text)

  const midpoint = Math.floor(
    characters.length / 2
  )

  const firstHalf = characters
    .slice(0, midpoint)
    .join('')

  return calculateHash(firstHalf)
}
```

При сравнении HASH-HALF учитывать длину сравниваемого префикса.

Не считать строки совпавшими исключительно по числовой сумме.

Строки могут находиться в любом порядке.

**Сравнение не должно зависеть от номера строки.**

### 16. Безопасность локальных файлов

Все операции с файловой системой выполняются локально.

Пользователь должен явно выбирать рабочую директорию.

Серверная часть должна проверять пути и запрещать доступ за пределы разрешённой директории.

Защититься от:
- Path traversal.
- Неожиданных символических ссылок.
- Случайной перезаписи исходного документа.
- Сохранения за пределами рабочей директории.

Перед массовым удалением или изменением файлов предусмотреть подтверждение.

Удаление зелёных строк сначала применяется только к состоянию редактора.

Важные технические уточнения
Есть три момента, которые особенно важно учесть при реализации.

1. HASH как сумма UTF-8 байтов не гарантирует уникальность. Например, строки AB и BA имеют одинаковую сумму — 131. Поэтому в промпте сохранён ваш алгоритм, но добавлена обязательная проверка реального текста. Это предотвращает ошибочное удаление строк.

2. HASH-HALF требует строгого определения половины. В промпте предложено делить строку по Unicode-символам, а затем суммировать байты первой половины. Для кириллицы это безопаснее, чем разрезать массив UTF-8 байтов посередине.

3. «Убрать зелёное» удаляет строки целиком, а не отдельные символы. Это соответствует задаче удаления совпадающих строк независимо от их порядка. Жёлтые строки сохраняются для дальнейшей ревизии.

Дополнительная рекомендация: для первой версии лучше сохранить именно вашу схему HASH + HASH-HALF + SQLite, а более сложные алгоритмы нечёткого сравнения добавить отдельным этапом. Так будет проще проверить корректность поиска, подсветки и удаления дубликатов.
